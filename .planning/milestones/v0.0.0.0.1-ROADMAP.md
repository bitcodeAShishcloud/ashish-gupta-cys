## Milestone Summary

**Key decisions:**
- SSE via same-origin `POST /api/chat` (CSP `connect-src 'self'`), client reads deltas with a ReadableStream reader
- Image delivery is client-direct from the provider CDN — the server never fetches provider URLs (Mimosa push-gate drove this; it also removed the SSRF sink class entirely)
- Style selection uses leading-clause prompt sentences that also generate the picker thumbnails — preview equals output
- All visitor data browser-only (name, two histories, usage counter) — zero cookies, zero server-side storage

**Issues encountered & resolved:**
- Model-provider subagent spawns blocked all session → everything planned/executed inline
- Mimosa push-gate blocked 3 pushes (SSRF advisory) → resolved by removing the sink instead of arguing with the scanner
- `next build` during `next dev` corrupted `.next` once → restart-on-clean-`.next` rule recorded in STATE.md
- Stale `(site)/chat` duplicate route broke the Vercel build → deletion committed separately (GSD commit tool skips pure deletions)
- Gateway rejects unsupported sizes → aspect map aligned to its supported set

**Tech debt / accepted risks:**
- In-memory rate limiting is per-lambda-instance (fine for a portfolio)
- Derived session secret when `ADMIN_SESSION_SECRET` unset (documented; owner can set it)
- Residual Mimosa advisory on env→fetch taint in `callProvider`/`streamProvider` (accepted: env is owner-controlled config, same trust model as the pre-existing chat proxy)
- No cancel button while generating; popover Escape-to-close (both logged in UI-REVIEW.md)
