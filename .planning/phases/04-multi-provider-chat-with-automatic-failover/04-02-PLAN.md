## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → POST /api/providers | Authenticated admin session (HMAC cookie); the new optional id widens what a caller can name — the guard order is the only thing standing between the public and provider enumeration |
| provider upstream → admin result line | Upstream error detail relayed into the admin DOM through the test-failure detail field |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Spoofing / Elevation of Privilege | app/api/providers/route.ts POST {id} | medium | mitigate | Auth guard (adminConfigured + isAdminRequest) stays the FIRST statement and the 6/min/IP rate limit the second; the 404 provider_not_found path is reachable only post-auth, so provider-id enumeration is not exposed to the public (Task 1 acceptance criteria fix the guard order) |
| T-04-06 | Information Disclosure | providers route test-failure detail | high | mitigate | The failure detail must redact the TARGET provider's apiKey (today it redacts the active one, so a standby test would leak its key) and keep the 300-char cap — Task 1 step 2 with a dedicated acceptance criterion (T-03-03 bar) |
| T-04-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager installs occur in this phase (04-AI-SPEC: no new dependencies); the legitimacy-gate protocol has nothing to gate; revisit if scope ever adds a dependency |
</threat_model>
