# Requirements: Ashish Gupta Cyber Security Portfolio (v2)

**Defined:** 2026-11-04
**Core Value:** A visitor can ask the embedded assistant about Ashish's skills, projects and security topics, and the experience — including the chat itself — should feel like it was handcrafted by Ashish, not generated by a tool.

## v0.0.0.0.2 Requirements

Requirements for this milestone. Each maps to roadmap phases.

### Provider layer

- [ ] **PROV-01**: Owner can configure multiple AI providers in `AI_PROVIDERS_JSON` and switch the active one by editing `activeId` only — no code changes
- [ ] **PROV-02**: If the active provider fails (HTTP error, timeout, malformed reply), `/api/chat` automatically retries once against the next configured provider and still returns a reply
- [ ] **PROV-03**: Admin console lists every configured provider with status, and the live provider test can target any configured provider — not just the active one

### Production deploy

- [ ] **DEPL-01**: Site deploys to Vercel and the chat works in production (streaming SSE, name gate, daily limit intact)
- [ ] **DEPL-02**: All production secrets live in Vercel env vars — `AI_PROVIDERS_JSON` (both providers), `AI_ALLOWED_HOSTS` (both hosts), `AI_IMAGE_CSP_HOSTS`, `ADMIN_USERNAME`/`ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`
- [ ] **DEPL-03**: Image-generation mode works on the deployed site (client-direct CDN rendering + download proxy with the CSP host env set)

### Security hygiene

- [ ] **SEC-01**: No API key in the repo, planning docs, or chat transcripts; keys pasted into chat are rotated; `.env.local` stays gitignored

## v2 Requirements

- **ENG-01**: Automated test coverage for the security-critical `lib/` functions

## Out of Scope

| Feature | Reason |
|---------|--------|
| Image generation via Top-Tools-AI | XKiro's async-job image endpoint works; switching image vendors is its own phase |
| Provider selection UI for visitors | Public chat stays provider-agnostic by design (de-branded presentation) |
| Database / server-side chat history | Product decision: everything stays in the visitor's browser |
| Automatic multi-provider load balancing | One retry-failover is enough for a portfolio site; load balancing adds failure modes without user value |
