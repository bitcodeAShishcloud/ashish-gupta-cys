# Requirements: Ashish Gupta Cyber Security Portfolio (v2)

**Defined:** 2026-11-04
**Core Value:** A visitor can ask the embedded assistant about Ashish's skills, projects and security topics, and the experience — including the chat itself — should feel like it was handcrafted by Ashish, not generated by a tool.

## v0.0.0.0.2 Requirements

Requirements for this milestone. Each maps to roadmap phases.

### Provider layer

- [x] **PROV-01**: Owner can configure multiple AI providers in `AI_PROVIDERS_JSON` and switch the active one by editing `activeId` only — no code changes
- [x] **PROV-02**: If the active provider fails (HTTP error, timeout, malformed reply), `/api/chat` automatically retries once against the next configured provider and still returns a reply
- [x] **PROV-03**: Admin console lists every configured provider with status, and the live provider test can target any configured provider — not just the active one

### Production deploy

- [x] **DEPL-01**: Site deploys to Vercel and the chat works in production (streaming SSE and the daily limit working as shipped by Phases 4/6)
- [x] **DEPL-02**: All production secrets live in Vercel env vars — `AI_PROVIDERS_JSON` (both providers), `AI_ALLOWED_HOSTS` (both hosts), `AI_IMAGE_CSP_HOSTS`, `ADMIN_USERNAME`/`ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`
- [x] **DEPL-03**: Image-generation mode works on the deployed site (client-direct CDN rendering + download proxy with the CSP host env set)

### Security hygiene

- [x] **SEC-01**: No API key in the repo, planning docs, or chat transcripts; keys pasted into chat are rotated; `.env.local` stays gitignored

### Chat access

- [x] **CHAT-04**: Visitor can start chatting immediately — no name prompt before the composer (chat page and widget both)
- [x] **CHAT-05**: Visitor gets 50 chats per day per device — client-side counter in localStorage, same approach as v0.0.0.0.1 (no server-side tracking)

## v0.0.0.0.3 Requirements

### Rich markdown

- [ ] **MD-01**: Every code block has an always-visible header bar with language label, line numbers, wrap toggle, Copy (with feedback), Download and Expand
- [ ] **MD-02**: Note / Tip / Important / Warning / Caution / Danger callouts render brand-monochrome, in chat and blog
- [ ] **MD-03**: LaTeX math (inline + display) and Mermaid diagrams render; headings get anchors; external links open safely
- [ ] **MD-04**: Every assistant message has an always-visible action bar — Copy, Copy-as (Markdown / Plain text / HTML / JSON / Email), Download (.md/.txt/.html/.json/.pdf/.docx), Share, Email (mailto), Print, Draft-email prompt, Regenerate
- [ ] **MD-05**: Chat header toolbar controls font size, font family, line spacing and reading width, persisted per device in localStorage
- [ ] **MD-06**: `SYSTEM_PROMPT` asks for consistent, well-structured replies (sections, lists, tagged code fences, tables, callouts)
- [ ] **MD-07**: Whole-conversation export is available; no server-side state is added
- [ ] **MD-08**: Streaming replies degrade gracefully on partially-written fences, math and diagrams

## v0.0.0.0.4 Requirements (Phase 8)

### Mail / draft replies

- [ ] **SEND-01**: Mail/draft replies show only `Copy` + `Send`; normal replies show `Copy`, `Copy as`, `Download`, `Share`, `Regenerate`
- [ ] **SEND-02**: `Send` opens the native share sheet (Web Share API) with Email-ready text (Subject + greeting + body + sign-off), falling back to clipboard on desktop
- [ ] **SEND-03**: `Email`, `Print` and `Draft email` buttons are removed from the codebase
- [ ] **SEND-04**: Mail type is signalled by a structured SSE event with a content-detection fallback; the bar never flashes during streaming
- [ ] **SEND-05**: A same-origin, SSRF-gated `/api/research` route fetches prospect info (auto web search + user-supplied link/paste) and the assistant produces a personalized outreach draft
- [ ] **SEND-06**: No visitor data is stored server-side; no new colours or hover-only affordances

> **Open items (owner must decide before planning):** research provider + API key, per-call cost/rate limit, manual-input UX, auto-detect false-positive policy, and whether research runs automatically on every message. See `08-CONTEXT.md`.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Image generation via Top-Tools-AI | XKiro's async-job image endpoint works; switching image vendors is its own phase |
| Provider selection UI for visitors | Public chat stays provider-agnostic by design (de-branded presentation) |
| Database / server-side chat history | Product decision: everything stays in the visitor's browser |
| Automatic multi-provider load balancing | One retry-failover is enough for a portfolio site; load balancing adds failure modes without user value |
| Server-side per-user daily quotas | Would add server state + identity; privacy model keeps all visitor data client-side (per-device limit only) |
